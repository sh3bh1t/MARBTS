Simulation Run

                
Rule and adaptive policy execution

              

              
            


            

              

                What This Screen Does
                
This page runs one seeded simulation. Red chooses offensive actions, Blue chooses defensive actions, the environment applies legal state transitions, and the UI shows the resulting graph and timeline.

              

              

                How To Explain It
                
“A run is deterministic for the same scenario, seed, horizon, and policy settings. That means we can replay and compare behavior instead of relying on one-off demonstrations.”

              

              

                Point Out
                
    
                  
  • Rule policies are fixed heuristics; adaptive policies score legal actions using planning, observability, and optional deception settings.
    • 
                  
  • The turn slider shows how the network changes after each Red and Blue action pair.
    • 
                  
  • The timeline includes rationale, targets, state changes, and compromise deltas.

Replay Artifacts

                
Run metadata, policy metrics, and timestep events

              

              
            


            

              

                What This Screen Shows
                
Replay reads the artifacts written by a run: metadata, timestep logs, policy metrics, provenance, and sequence hashes. It is the audit trail for what happened.

              

              

                How To Explain It
                
“The simulator is not just drawing a final answer. Every decision is stored as an event, so we can inspect the exact sequence and verify that replay matches the recorded policy metrics.”

              

              

                Point Out
                
    
                  
  • Run IDs are deterministic hashes of configuration and initial state.
    • 
                  
  • Integrity OK means the replayed action sequence matches the stored metrics artifact.
    • 
                  
  • The timeline is useful for explaining why a metric changed, not just that it changed.

Reports

                
Experiment packages and comparative outputs

              

              
            


            

              

                What This Screen Produces
                
Reports turn individual simulations into research artifacts. They aggregate multiple seeds, compare policy families, package ablation results, stress scenarios, and compare two run directories.

              

              

                How To Explain It
                
“A single run tells a story; reports tell whether the story is stable. This is where we move from a demonstration to repeatable evaluation.”

              

              

                Point Out
                
    
                  
  • Multi-seed reports measure reproducibility and outcome spread.
    • 
                  
  • Policy matrices compare rule and adaptive Red/Blue combinations plus ablations.
    • 
                  
  • The artifact viewer lets you inspect generated JSON and Markdown without leaving the UI.

Operations

                
Release gates and container execution profiles

              

            


            

              

                What This Screen Checks
                
Operations focuses on delivery readiness. Release validation checks expected project assets and configuration, while container profiles resolve reproducible Docker Compose commands.

              

              

                How To Explain It
                
“This is the handoff surface. It shows whether the repo is packaged, documented, configured, and runnable in the expected ways.”

              

              

                Point Out
                
    
                  
  • Release gates are concrete pass/fail checks tied to files, scripts, presets, notebooks, and docs.
    • 
                  
  • Container profiles show exactly which compose service and command would run.
    • 
                  
  • Dry-run resolution is safer for demos; execute only when Docker is available and intended.
